01Overview

A frontier coding agent (Claude Code, Codex, …) is dropped into an isolated container holding exactly three things — a minimal, boot-verified copy of the benchmark, the task, and an empty workspace — and asked to write a program that makes the robot solve the task. Nothing to copy, nothing to tamper with — the only way to succeed is to solve the task.

The lifecycle

once per machineBuild the docker imagesthe simulator and the agent CLIs, installed into reusable images. The benchmark is never baked in — an image knows nothing about any task.
once per experimentBuild the worlddistill a minimal benchmark for one registered task, apply any ablation surgery, boot-prove it, seal it with a receipt.
once per runRun the agenta disposable container: the proven world read-only, one writable workspace, guarded network. At the deadline the container dies; the workspace survives.
per submission · openAuto-gradethe submitted solution is replayed in a second isolated container — the exact same world, plus the private verifiers. The agent may do anything during its run; only what passes here counts. Details still undecided.

Each boundary is also a trust boundary: images know no tasks, worlds are sealed before any agent exists, and the verifiers only ever appear in the grader's container — never the agent's.

What keeps it honest

  • Tasks come from registered, verified configs. Every registered scene–robot pairing has been solved at least once, so an agent is never handed an impossible world.
  • Nothing to cheat with. The container holds no solutions, no verifiers, no demo scripts; the benchmark is read-only and the network reaches only the model API and the package index.

02Build the docker images

Everything an agent run needs except the benchmark itself, baked once into layered images: the Isaac simulator stack in a ready venv, and the agent CLIs on top. Benchmark changes never require a rebuild.

Install

# 0 · host prerequisites — docker, NVIDIA container toolkit, CDI spec. # CDI is mandatory (legacy --gpus breaks Vulkan/RTX): see eval/docker/INSTALL.md # after every NVIDIA driver upgrade: sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml # 1 · sanity checks (small image, GPU passthrough, agent CLI): make test-image && make test-gpu && make test-claude # 2 · the real images: make l0 # 30–60 min, once make warm # boots the baked venv once, warms the shader cache make l1 CC_VERSION=$(npm view @anthropic-ai/claude-code version) # minutes

All make targets live in eval/docker/Makefile. Credentials are never baked into images — they enter later, per run, through environment variables.

03Build the experiment folder

One command turns a registered task into a self-contained, boot-proven folder on disk — the world the agent will later be locked into.

python3 eval/scripts/build_env.py --name bulb_smoke --stage bulb:franka # --list show all registered presets # --stage scene:robot[:controller] — controller defaults osc > impedance > joint # --no-set-states ablation: disable snapshot-restore; solve from reset() forward # transfer test: repeat --stage to build an ordered sequence — e.g. skills carried to a new scene: python3 eval/scripts/build_env.py --name screw_transfer --stage bulb:franka --stage nut_thread:franka # each stage gets its own bench/; the agent keeps its workspace files from stage 01 into stage 02

What it does

resolveintent → registered preset, else fail with the menu of what exists
extractminimal benchmark tree: no other suites, no demo scripts, only the assets this task needs; solve-provenance comments scrubbed
patchablations rewritten into the tree's code (e.g. --no-set-states)
boot-provelaunch the sim from the extracted tree and reset the actual preset — no world ships unbooted
receiptcontent hash + repo revision + argv, so every result is attributable to exact code

What lands on disk

experiments/bulb_smoke/ ├─ resolved.json receipt: argv · preset · hashes · repo revision ├─ MANIFEST human-readable summary ├─ stages/01_bulb_franka/ │ ├─ bench/ minimal benchmark tree, boot-proven (~141 MB for bulb) │ └─ describe.txt the scene's describe(), harvested during the boot └─ runs/ created later, one per agent run

Everything environmental fails here, at build time — unregistered combos, missing assets, broken presets. At agent time, a failure is the agent's. Task-prompt rendering is currently unplugged while the prompt design is revisited; describe.txt keeps the raw material.

04Run experiments deferred

The experiment runner — which agents, how many repeats, stage sequencing for transfer, what gets measured — is future work, waiting on the prompt design. What is already fixed and proven is the container contract underneath it: one run = one disposable container over a built experiment, killed at its budget.

eval/scripts/run_agent.py exists as a reference single-run launcher against that contract (dry-run tested; credentials ride shell env vars, never stored).

The container contract — what the agent sees

stages/01_…/bench/
→ ro
/bench import robobench = this tree, nothing else
stages/01_…/task/
→ ro
/task the task instruction (optional while prompts are redesigned)
runs/<r>/workspace/
↔ rw
/workspace the only writable dir; visible on the host live
docker volume rb-ovcache
↔ rw
/ovcache shared shader cache
baked in the image, not mounted: /opt/venv (Isaac) · agent CLIs — and nothing of the repo

The repo, your experiments, solutions, and .git do not exist inside the container. run_agent.py runs open-network for development; results that count go through eval/docker/compose.agent.yaml, whose egress allowlist admits only the model API and the package index (GitHub blocked — the public repo's history cites solve-calibrated configs).

05Auto-grade not built yet

The shape is decided; the details are deliberately not. What is fixed: grading replays the submitted solution in a second isolated container — the exact same world as the agent's, plus the private verifiers, which never appear in the agent's container. The agent may do anything during its run; only what passes the replay counts.

Verifier design, metrics, and scheduling are open. Runs archive everything raw so no option is closed.

Proven by oracle replay — e.g. the bulb solve, seated in-sandbox on video.
