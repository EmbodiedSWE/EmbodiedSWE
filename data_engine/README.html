01Overview

A coding agent solves a robobench task once. The data engine multiplies that single verified solve into a large, diverse, per-episode-verified demonstration dataset.

Three decoupled stages: diversify — agents write the code that adds diversity (scenes, strategies, phases, resets); generate — one generic launcher mass-produces batched episodes from whatever is authored; verify — the scene's grader stamps a verdict on every episode. Verification is also the feedback on the code: agents test-launch small batches mid-session, and each batch's success rate is documented — informing further authoring and repair.

Hierarchical diversification

The engine diversifies the scene and the solve along a hierarchy where each level contains the next: one scene hosts many strategies; each strategy breaks into phases, re-enterable from many sampled states; dynamics perturb every rollout; every rollout re-renders visually. Each level can be run independently — none is mandatory, none waits on another, and the downstream experiment picks the subset it needs.

02Diversification levels

One subsection per level of the hierarchy — the rules, the examples, and the checks each level runs at acceptance.

L1 · scene

Irrelevant objects (an apple beside the bulb): collision-safe placement only — grader and solve untouched; assets from the prebuilt pipeline. Relevant objects (three nuts, seat them all): task semantics change — prefer parameterizing the proven grader (num_pairs already exists in the scenes) over rewriting it. A genuinely new criterion is bench authoring: human-reviewed, sanity-tested (reference solve passes, null rollout fails).

L2 · strategy

Enumerable choices (approach side, execution order) are surfaced as solver arguments at solve time and sampled at script cost forever. Structural mutants (hand the ikea leg to the other arm and let it screw; dome grasp vs neck grasp) take one agent session each, with the grader as the acceptance test plus a distinctness check — a "new" strategy that collapses into an existing one inflates K nominally.

L3 · phase

Checkpoints at phase boundaries (recorded phase codes make them machine-readable; agents may add mid-phase ones). Restore into all envs, perturb, resume with fresh calibrations. Perturbation mode follows the grasp-coupling rule: object free → move it alone (initial-condition randomization entering at tk); object grasped → rigid hand+object transform + re-IK (the MimicGen relocation idea, executed closed-loop). Safe re-entry points are measured, not declared — probe batches per boundary, keep what yields.

L4 · dynamics

DART-style action noise: perturb the executed action, record the clean action as the label — the recovery-teaching signal. Physics parameters (friction, mass) sample per round; some are solvability-tuned, so expect asymmetric bands. All of it generic; per-task only σ and bands, found by sample-and-filter.

L5 · visual

Free, and retroactive: pixels come from replaying recorded states, so k visual variants per episode cost render time only — no physics, and it applies to every episode ever recorded.

03Generating data

The diversification levels produce code; this stage turns it into episodes. Generation is one generic command over any authored cell — a (scene, strategy, phase) triple — with no task-specific logic anywhere in the launcher.

Init — from eval run to the first spine

scaffoldcreate scenes/scene_0/: unblocked suite scene + cfg into scene/, suite grader into grader/
portthe eval solution → strategy_0/phases/phase_0/solve.py; mechanical if it followed the batch prompt rule
default resetphase_0/reset.py = the scene's own seeded reset + IC bands
gaterun a nominal batch, grade it, write it to data/default/ — scene_0 · strategy_0 · phase_0 at nominal is the campaign's control cell; if it doesn't yield, the harness is broken, not the diversification

Sampling — one generic sampler over declared dims

Every *.yaml entry is one of a typed schema defined once in python — Range (continuous band), Choice (discrete options — values or names, e.g. which reset function), Const (frozen, reason required) — validated at load, so a typo fails in seconds, not an hour into a batch. The runner derives θ as a pure function of the episode index (low-discrepancy over ranges, cycled choices, index 0 = nominal) and routes it: scene dims → build/reset, solver dims → solve.py args, reset choice → the named function in reset.py. The drawn θ is recorded in each episode's meta.json — the yaml is the menu, the meta is what happened.

One batch, end to end

pick cellsany (scene × strategy × phase) triples + episode budget — whatever is authored and gated
sampleθ per episode index from the yamls: bands, choices, reset strategies; index 0 = nominal
roll outE envs × rounds on one GPU; each env enters at its phase via the sampled reset, runs to task-done
gradethe scene's grader judges every episode — the only quality gate there is
writeep folders + batch meta into data/<batch>/; failures kept with their θ for yield curves; level metas refreshed

Under the hood — runner and solver

The runner owns everything repetitive about batched execution; a solver plugs in through three hooks — so the runner is written once and executes any compliant solver at any num_envs:

setup(env) # once: controller retunes, one-off calibration fresh_state(entry_phase) -> dict # per-env FSM state, enterable at ANY phase step(obs_e, st) -> action_row | ("done"|"abort", verdict)

Each control tick the runner pulls all state in a few batched CPU transfers, steps every env's FSM on that snapshot, perturbs the executed actions (clean actions go to the record), steps physics as one (E, action_dim) tensor, and records arrays + per-step phase codes with an exact snapshot at each phase transition. Done envs hold a zero-delta action until the round ends.

Properties

Independent and parallel Every (scene, strategy, phase) cell generates in its own process — across GPUs, no coordination — because θ is a pure function of the episode index.
Reproducible, append-only Re-running a batch re-derives the same θ sequence; same build + seed → byte-identical rollouts. Across code changes contact chaos diverges — validate by milestones, never trajectory equality.
Nominal cells are the controls scene_0 · strategy_0 · phase_0 at θ-nominal must keep yielding; when it stops, the harness broke — not the diversification.
Cost profile Isaac boots in ~75 s, then rounds are nearly free (E × rounds episodes per process) — but a round runs as long as its slowest env, so early-abort on detectable failure signatures is the main lever.
